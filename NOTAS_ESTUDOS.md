# Etapa 1 - Pesquisa Conceitual

## 1. O que difere um Projeto de Software de um Script/Código Isolado?

Um **Projeto de Software** é um conjunto de atividades planejadas para desenvolver um sistema que atenda às necessidades de um cliente ou organização. Ele possui objetivos definidos, requisitos, planejamento, documentação, testes, manutenção e geralmente envolve uma equipe de desenvolvimento.

Um **Script** ou **Código Isolado** é um programa criado para executar uma tarefa específica, normalmente de forma simples e sem um processo formal de desenvolvimento. Geralmente não possui documentação, planejamento ou manutenção contínua.

### Principais diferenças

| Projeto de Software | Script/Código Isolado |
|---------------------|-----------------------|
| Possui planejamento | Geralmente é criado para uma tarefa específica |
| Tem requisitos definidos | Normalmente não possui requisitos documentados |
| Utiliza controle de versões | Nem sempre utiliza versionamento |
| Possui testes e manutenção | Geralmente não recebe manutenção contínua |
| Pode envolver uma equipe | Normalmente é desenvolvido por uma única pessoa |

---

## 2. Ciclo de Vida Básico de um Projeto de Software

### Levantamento de Requisitos / Escopo

Nesta etapa são identificadas as necessidades do cliente e definidas as funcionalidades que o sistema deverá possuir. Também são estabelecidos os objetivos, limitações, prazos e recursos do projeto.

---

### Desenvolvimento / Codificação

É a fase em que os desenvolvedores escrevem o código-fonte, implementam as funcionalidades planejadas e organizam o projeto utilizando boas práticas de programação.

---

### Testes / Qualidade

Após o desenvolvimento, o sistema é testado para verificar se todas as funcionalidades estão funcionando corretamente. O objetivo é identificar e corrigir erros antes da entrega ao cliente.

---

### Entrega / Implantação

É a etapa final, na qual o software é disponibilizado para uso do cliente ou colocado em funcionamento no ambiente de produção. Após a implantação, podem ser realizadas manutenções e atualizações quando necessário.

---

## 3. Por que definir um escopo fechado antes de iniciar a codificação é importante?

Definir um escopo antes do início do desenvolvimento é fundamental porque estabelece exatamente o que será desenvolvido, evitando mudanças constantes durante o projeto. Isso facilita o planejamento, melhora a organização da equipe, reduz atrasos, evita desperdício de tempo e recursos e aumenta as chances de entregar o software dentro do prazo e conforme as expectativas do cliente.

Além disso, um escopo bem definido permite estimar custos, distribuir tarefas corretamente e controlar melhor o andamento do projeto.

---

# Conclusão

O desenvolvimento de software exige planejamento, organização e controle durante todas as etapas do projeto. O ciclo de vida do software ajuda a garantir que o sistema seja desenvolvido com qualidade, enquanto ferramentas como o Git permitem registrar todas as alterações realizadas, facilitando o trabalho em equipe e o gerenciamento das versões do projeto.
